## 2. Masalah yang Ditemukan (Bugs) & Solusi

### Bug 1: MemAvailable Overflow / MGLRU Active Page Counter Leak
* **Gejala**:
  - Di Settings / Termux, sisa RAM terbaca hingga puluhan GB (abnormal) pada device 4GB RAM ("ram bug.jpg").
  - Sistem rentan crash Out of Memory (OOM) karena kernel salah menghitung kapasitas RAM bebas.
* **Akar Masalah (Root Cause)**:
  - Pada arsitektur Multi-Gen LRU (MGLRU) backport ke 4.19, makro `set_mask_bits` di `include/linux/bitops.h`:
    ```c
    #define set_mask_bits(ptr, _mask, _bits) ({ ... new__; })
    ```
    Makro tersebut mengembalikan nilai baru (`new__`), padahal MGLRU mengharapkan nilai lama (`old__`).
  - Akibatnya pada fungsi `lru_gen_del_page()`, penentuan generasi halaman lama (`page_to_gen`) selalu bernilai `-1`.
  - Pada `lru_gen_update_size()`, kondisi `old_gen == -1` diterjemahkan sebagai penambahan halaman baru, bukan pengurangan. Setiap kali RAM membebaskan halaman, counter memori aktif justru bertambah terus tanpa batas.
* **Solusi**:
  - Memperbaiki `set_mask_bits` agar mengembalikan `old__`.
  - Menjaga kalkulasi generasi halaman pada `lru_gen_del_page` tetap akurat.
* **Commit**: `44941fa`, `7d8fb46` (PR #3, #2).

### Bug 2: YouTube ReVanced / Morphe Force Close
* **Gejala**:
  - Aplikasi yang membutuhkan modul KernelSU (seperti YouTube ReVanced dengan module mount) langsung crash saat dibuka.
* **Akar Masalah (Root Cause)**:
  - Pada hook `setresuid`, fungsi `susfs_try_umount_all(uid)` dipanggil secara agresif untuk semua UID tanpa filter.
  - Direktori `/product` dan `/data/adb/modules` langsung di-unmount dari mount namespace ReVanced.
* **Solusi**:
  - Tambahkan pengecekan profil KernelSU:
    ```c
    if ((is_isolated_process(new_uid) || ksu_uid_should_umount(new_uid)) && is_zygote(current_cred())) {
        susfs_try_umount_all(new_uid);
    }
    ```
  - Aplikasi yang diizinkan modul di KSU Manager tidak akan di-unmount.
* **Commit**: `814b864` (PR #4).

### Bug 3: SuSFS Versi "Unknown" di KernelSU Manager
* **Gejala**:
  - Menu SuSFS di KernelSU Manager menampilkan status modul tidak dikenal (Unknown).
* **Akar Masalah (Root Cause)**:
  - KernelSU Manager versi 3.x querying status SuSFS lewat syscall:
    `reboot(0xDEADBEEF, 0xFAFAFAFA, CMD_SUSFS_SHOW_*)` via tool `ksud`.
  - Hook `kernel/reboot.c` dan `supercall.c` belum memiliki handler untuk memproses command SuSFS tersebut pada kernel 4.19.
* **Solusi**:
  - Menambahkan dispatch parser `ksu_handle_susfs_sys_reboot` ke `supercall.c` dan memasang interceptor di `kernel/reboot.c`.
* **Commit**: `e2bca06`, `15c5c69`.
