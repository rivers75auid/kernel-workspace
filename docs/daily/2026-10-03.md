## 2. Masalah yang Ditemukan (Bugs) & Solusi

### Bug 1: Syscall `execveat` Terblokir Register `envp` di `syscall_table_hook.c`
* **Gejala**:
  - Aplikasi bank tetap force close meskipun modul BRENE dicopot dan `sus_map` sudah terpasang.
  - Kernel umount sama sekali tidak berjalan untuk semua aplikasi di runtime.
* **Akar Masalah Mendalam (Root Cause)**:
  - Pada Android ARM64, libc bionic menerjemahkan setiap pemanggilan `execve()` menjadi syscall:
    `execveat(AT_FDCWD, path, argv, envp, 0)`
  - Di `syscall_table_hook.c`, interceptor dipasang di balik pengecekan:
    ```c
    if ((int)PT_REGS_PARM1(regs) == AT_FDCWD && (int)PT_REGS_SYSCALL_PARM4(regs) == 0) {
        if (current->pid != 1 && is_init(current_cred())) {
            ksu_handle_execve_ksud(*filename_user, ...);
        }
    }
    ```
  - **Letak Kesalahan**:
    Pada ABI ARM64 Linux, register pemanggilan adalah:
    - `PARM1`: `regs[0]` (`dfd`)
    - `PARM2`: `regs[1]` (`filename`)
    - `PARM3`: `regs[2]` (`argv`)
    - `PARM4`: `regs[3]` (`envp`)
    - `PARM5`: `regs[4]` (`flags`)
  - Pengecekan `PARM4 == 0` mengira ia sedang mengecek `flags == 0`. Padahal ia mengecek pointer environment `envp`, yang di Android **tidak pernah bernilai 0**.
  - **Efek Domino Fatal**:
    1. Handler `ksu_handle_execve_ksud` **tidak pernah terpanggil seumur hidup device**.
    2. KernelSU gagal mendeteksi eksekusi `init second_stage`.
    3. Task work `ksu_initialize_selinux_tw_func` tidak pernah dijadwalkan.
    4. Fungsi `cache_sid()` dan `setup_ksu_cred()` **mati total**.
    5. Kredensial root kernel (`ksu_cred`) selalu bernilai `NULL`.
    6. Saat aplikasi bank dibuka, fungsi `kernel_umount` memeriksa:
       ```c
       if (!ksu_cred) return 0;
       ```
       Karena `ksu_cred == NULL`, proses unmount langsung dibatalkan!
    7. Akibatnya, seluruh mountpoint root dan modul terbuka lebar ke aplikasi bank.
* **Solusi**:
  - Eksekusi `ksu_handle_execve_ksud` langsung pada setiap pemanggilan `execveat` tanpa terhalang register `envp`.
  - Inisialisasi `ksu_cred` dan SID Zygote kini berjalan sempurna saat boot.
* **Commit**: `5216a45`.

### 3. Upgrade Toolchain: ZyC Clang 16.0.6 (LLVM Polly)
* **Analisis Toolchain**:
  - **Proton Clang 13 (2021)**: Terlalu tua, optimasi pipeline CPU generasi baru terbatas.
  - **Neutron Clang (LLVM 19/20)**: Terlalu agresif untuk kernel 4.19 CAF, memicu ratusan error warning `-Werror` pada driver audio/soc lama.
  - **ZyC Clang 16.0.6**: Sweet spot sempurna. Dilengkapi **LLVM Polly Loop Optimizer** yang mengoptimalkan loop vektorisasi SIMD NEON pada core Kryo 265 (4x Cortex-A73 + 4x Cortex-A53) Snapdragon 680.
* **Implementasi**:
  - Mengupdate `.github/workflows/build-kernel.yml` untuk mengunduh rilis `Clang-16.0.6-20260807-release`.
* **Commit**: `5216a45`.
